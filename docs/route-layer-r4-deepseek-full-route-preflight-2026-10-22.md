# R4 DeepSeek 完整路线零请求预检（2026-10-22）

## 结论

本次只运行本地构包、schema 序列化、路径长度统计和费用量级估算：**DeepSeek/Codex 模型请求 0 次、API key 未读取、正式批次未启动**。

完整路线一次返回可以避免逐边调用时反复发送地图，但当前 strict schema 和输出上限还没有形成可靠的 100×100 准入门禁。当前 schema 将单条路线长度放宽到局部包节点数减一（中位数 4,262 条边，最大 9,999 条），而 `run_route_r4_smoke.py` 默认只给 128 output tokens、可显式提高的最高值为 1,024。按 9,999 条边生成当前输出结构约需 40,157 字节；不能据此保证模型能在输出上限内完成。

**因此本次没有把完整路线方案冻结为正式 R4，也没有启动十种子批次。**

## 输入与任务覆盖

- 来源：传统路线实验冻结的 seed 0–9 地图、订单、正式场景和已有全图 Dijkstra 结果。
- 共 150 个任务实例；本次完整路线请求尺寸只统计离线有向可达的 130 个任务。另 20 个（10 个非法端点、10 个不可达）在路由前失败分支中排除 API 请求尺寸；正式结果仍须为这 20 个任务保留失败记录，不可从结果集删除。
- 语义订单的局部路线包按“上游 Qwen 已正确选出端点”这一条件构造，使用冻结映射估算尺寸；路线请求只含已选端点 ID，不含 `true_*` / `ground_truth` 字段。**这不评价 Qwen 地点解析，也不构成语义端点实验结果。**
- 路线提示未含评估真值字段名；全图 Dijkstra 轨迹只用于离线对照输出长度，从未放入模型提示。

## 当前完整路线请求的尺寸

| 尺寸（130 个任务/一组） | 中位数 | P90 | P95 | 最大值 | 总字节数 |
|---|---:|---:|---:|---:|---:|
| system/user 消息 | 23,593 | 38,337 | 40,501 | 46,691 | 3,271,336 |
| DeepSeek strict 工具 schema | 17,957 | 32,279 | 34,350 | 40,236 | 2,518,518 |
| 序列化请求体（不含认证头） | 42,257 | 71,407 | 75,640 | 87,736 | 5,886,624 |

全图 Dijkstra 已存路线长度用于输出尺寸参照：均值 129.4 边，中位数 123，P90 203，P95 226，最大 264；离线最少有向步数的最大值也为 264。这些是传统路线/步数参照，**不是 R4 生成路线长度**。当前 3 位 edge-slot 编码加每边 1 位自检标记时，对应完整 JSON 输出大小中位数 653 字节、P95 1,065 字节、最大 1,217 字节。

传统路线长度下，如果把输出编码换成每边一个方向字符、保留一位自检，JSON 输出大小中位数约 401 字节、P95 608 字节、最大 684 字节，较当前 edge-slot 格式少约 39%。再把同一地图和端点提示改成方向串契约，构造一个**未采用的严格方向字符 schema 候选**：schema 中位/最大 695 字节，130 任务合计 90,288 字节；消息与 schema 共 3,281,024 字节，比当前 5,789,854 字节少 43.33%。请求体合计从 5,886,624 降到 3,371,814 字节。按同两种历史 token/字节代理，该候选单组输入费用约 ¥3.12–¥5.12（当前代理 ¥5.50–¥9.03），都不含输出费/本地 Qwen 费用，且都不是报价或上限。

方向 schema 只能限制 `E/W/N/S` 字符和长度，无法在 schema 层确认“当前节点走 E”确实有这条有向边。每个候选仍须由本地程序逐边检查出边、连续性、边界、上车/下车顺序、重复节点；有任一失败就把整条路线标为失败，不执行、不接纳、不用 Dijkstra/A* 修复。这样能保证**违规路线不进入有效结果**，但不能保证模型永远不提出非法方向；失败提议仍消耗一次请求。若保持现有 9,999 边 schema 长度，方向串完整 JSON 仍可达约 20,154 字节，故长绕行仍可能触及 1,024-token 输出上限。

## Token 与费用代理

对照 2026-10-19 保存的一次 8×8 DeepSeek full-route 失败请求：2,405 input tokens、6,334 消息字节、1,261 schema 字节；另一条已存 R4 stepwise smoke 为 40,270 input tokens / 77,463 消息字节。把这两个不同输入的 token/字节比率分别套到本次 130 个任务的消息和 schema，总输入量代理约为 **183 万–301 万 token/组**。按项目价格配置 `¥0.000003/token`，单请求输入费用代理约 **¥5.50–¥9.03/组**；若每个任务最多重规划三次，则约 **¥16.50–¥27.09/组**。若 R4、R4-A、R4-B 三组都采用同样输入和三次上限，线性外推上端约 ¥81.27。

这些数是跨 8×8 与 100×100 的**字节比率代理**，不是 DeepSeek 报价、账单或硬上限。尚未计输出 token、重规划反馈额外字节、本地 Qwen 推理、语义解析失败分支；R4-A/B 输入不同，不能直接视作三组预算。一次 8×8 full-route 失败输出为 212 output tokens / 327 个参数字符，也不足以校准 100×100 的输出 token 数。

## 对“不允许违规”的含义

当前 strict schema 只保证每个 3 位 slot code 对应地图中存在的一条有向边，不能保证整个序列连续、按“起点→上车点→下车点”到达或没有重复节点。R4 本地确定性验证器会逐边检查方向、连续性、端点顺序和整条路线；任何一项失败，整条模型提议都不接纳为路线，不用 Dijkstra/A* 兜底。因而可以保证**违规路线不进入有效结果**，但不能保证模型永不提出违规候选；拒绝的候选仍会消耗该次已发请求的 token，并应作为失败保存。

## 尚未通过的准入项

1. 正式命令必须显式指定 `--max-output-tokens 1024`；当前默认 128 不能直接用于完整路线生成。
2. 输出 tokenizer 未针对 100×100 完整路线验证。最短路/传统路线 JSON 最大 1,217 字节看起来可能落在 1,024 token 内，但模型可能绕行，且字符数不能精确换算 token。
3. strict schema 的最大路线长度远大于输出预算；不能简单把它限制为 264，因为 264 是观测到的最短步数上限，不保证时间优先路线或绕行仍在此范围。
4. 每个任务失败后是否允许再请求、最多几次、请求前如何估算剩余额度尚未冻结。不得遇到截断后自动追加请求；必须由批次级硬预算决定。
5. 需明确非法端点和不可达 20 个任务如何以零模型请求记入失败结果，同时保持 150 项结果账本完整。

## 下一步建议

零请求比较显示，**方向串 + 每边一个自检字符 + 本地整条拒绝门禁**的输入和输出都更省，仍能保证任何违规路线不被接纳；代价是模型的非法方向提议不能由 schema 提前挡掉。建议把它作为下一版候选协议：先离线改造 runner、设置单次请求/零网络重试/费用熔断并做完整回归，再向你申请**一次** 100×100 单任务 DeepSeek 验证。该协议仍未获正式采纳，也未发出该请求。
