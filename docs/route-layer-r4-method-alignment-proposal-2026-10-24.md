# 路线层 R4 三组协议对齐建议（待冻结）

日期：2026-10-24  
状态：方法对齐草案；尚未成为正式冻结方案；本文件不包含模型实验结果。

## 需要对齐的差异

实验方案第 5.1 节的旧表仍把 R4-A/R4-B 写成 DeepSeek 整路线提议；第 10.3 节当前 R4 已改为 Codex CLI 每次提议一个方向。直接按旧表运行会同时改变模型后端和路线交互方式，无法把差异归因到地图输入或验证反馈。

## 建议使用的共同协议

三组都复用相同的冻结地图、订单/场景、Qwen 端点解析结果、Codex 模型及推理强度、紧凑有向图、动态方向 schema、本地路线校验器、动作/请求预算和电耗评估器。每次模型请求只提议一个方向。仅本地校验通过的边才会推进路线；拒绝提议保持未执行，记录错误类别，不使用 Dijkstra/A* 兜底；网络层重试数为零。

| 条件 | 路线请求中的道路特征上下文 | 本地验证失败后的行为 | 唯一改变的变量 |
|---|---|---|---|
| R4 | 提供经白名单校验的 `RoadFeatureInputProtocol v1` 相关特征与关系 | 生成简短结构化错误反馈，在同一节点重新请求；受共同请求上限约束 | 主方法 |
| R4-A | 不提供道路特征语义片段，仅保留相同拓扑/成本图和相同解析后的端点 | 与 R4 相同，发送相同格式的验证反馈 | 路线生成阶段是否能读取道路特征上下文 |
| R4-B | 与 R4 完全相同 | 不发送验证反馈；第一次本地拒绝后停止该任务并保留合法前缀 | 是否使用验证反馈重规划 |

R4-A 仍使用同一份冻结 Qwen 端点解析结果，因而检验的是路线生成阶段的道路特征上下文，不检验自然语言端点解析能力。R4-B 中本地校验仍照常执行；关闭反馈不表示接受非法动作，非法动作仍不会执行或进入路线状态。

## 分母、预算和报告口径

十种子冻结预检共 150 项：129 项可路由、10 项预设不可达、10 项非法端点、1 项语义关系解析失败。各状态都保留在150项分母中；不向拒绝的端点或不可达任务发路线模型请求，也不以真值修补语义失败。

当前单步协议在129项可路由任务上的动作下界合计17,072。若三组均采用此单步协议，则完成所有可路由任务的条件性最低请求量为每组17,072、三组51,216；这不包含验证拒绝后的反馈请求，不是 token、费用或账户额度估算。正式请求上限、时间上限和账户用量熔断仍需先以完整路线试跑用量制定。

### 零请求分段方案敏感性（未选定）

使用冻结预检中每项任务的最短动作数，离线计算每个模型响应最多提议 K 步时的请求数下界。所有路线仍由本地程序按顺序逐边校验；遇到第一条非法边即停止并拒绝该动作及其后缀，不执行非法移动。此模式不能用动态 schema 预先保证同一响应中的每个后续方向都合法，因此模型仍可能提出违规候选；它只保证非法动作不会被接纳或执行。是否接受这个差别，需要先冻结方法。

| 每次最多提议步数 K | 129项任务的请求下界 | 重复输入载荷字节下界 |
|---:|---:|---:|
| 1（当前动态单步schema） | 17,072 | 444,253,584 |
| 2 | 8,568 | 222,849,041 |
| 5 | 3,463 | 89,982,641 |
| 10 | 1,758 | 45,564,057 |
| 20 | 907 | 23,427,756 |

以上字节数按每项任务的首次 prompt+schema 载荷乘以其最短路径分段数，只是重复输入载荷的条件性下界；没有估算 tokenizer、反馈、输出、较长绕行或真实账单。K>1 会改变“每次只输出一个方向”的当前 R4 协议，不能直接用于正式实验。

### 单步会话复用候选（保持当前路线协议）

为减少逐步请求重复发送整张地图，可为每个任务单独保留 Codex CLI 会话：首个请求包含完整紧凑地图、道路特征上下文和规则；后续请求只提交当前节点、已访问状态与本步动态允许方向。模型仍每次只提议一个方向；每次请求都重新生成方向 schema，程序仍逐边校验，只有合法动作才推进状态。会话不得跨任务复用。

执行器离线复算当前 seed 0 task9 状态时，首个完整 prompt 为 16,327 字节；下一步的状态更新 prompt 为 387 字节，不含地图字段，为首个 prompt 的 2.37%。这是提交给 CLI 的 prompt 字节比较，不是模型实际计费 token；Codex 可能仍把会话上下文计入每轮 usage，必须从实际单步续跑的 `input_tokens`、`cached_input_tokens` 和账户用量变化验证节省幅度。

代码已提供显式 `--codex-session-mode persistent_per_task` 续跑选项，默认仍为每请求隔离会话；本地测试只验证状态续接、每步 schema 和小型状态 prompt，没有调用模型。因此该选项是待实测的输入传输优化，不是已确认的 token/额度优化，也还没有成为正式 R4 全批次配置。

任务完成率、合法路线率、拒绝提议数、完整路线距离/时间/能耗、模型 token 与延迟分别报告。完整路线未完成时，完整路线能耗标记为未评估；拒绝动作的实际车辆能耗为零，假设执行耗电仅作单独估计。

## 当前实现与验证

`route_experiment.r4_stepwise.run_r4_stepwise_route_search` 已新增 `enable_validation_feedback` 参数，默认 `true` 保持 R4 现有反馈行为；设为 `false` 后，本地拒绝或格式错误立即终止当前任务，状态为 `validation_rejected_without_feedback`。离线测试覆盖非法移动、可恢复的 `give_up` 和无效 JSON；此前已有测试覆盖默认 R4 会在相同状态发送结构化反馈并继续。Codex task9 专用试跑器维持原来的零重试、首次无效即停策略，未因此改变。

此开关只证明消融运行方式已能离线执行。它没有调用 Codex、没有证明模型效果或费用，也没有改变当前 task9 的 `quota_cap_reached` 状态。正式方案在用户确认前仍以原实验设计为准；R4-A/B 不得当作已冻结条件运行。
