# 纯 LLM 路线实验 v8 运行记录

日期：2026-10-18  
结果目录：`outputs/route_layer/pure_llm_experiment_v8/`

## 运行口径

- 地图：100×100，seed 0–9；每个 seed 10 个订单和 5 个正式场景，共 150 个任务。
- 方法：DeepSeek Flash 纯 LLM；每个任务一次 API 请求，`retries=0`；没有额外健康检查、调试请求或非路线任务请求。
- 地图输入：`grid-directed-mask-v2`、`graph_only`。向模型提供路网有向出口掩码、边界、端点合法性和普通地标；不提供路牌、电线杆、道路侧别、朝向或配对节点等 Agent-readable 特征。
- 约束边界：路线由 LLM 生成；程序只在返回后统一校验和记录，不使用 Dijkstra/A* 限制、修复或回退路线。
- 输出上限：1,024 tokens；reasoning effort 为 `none`；超时 90 秒。

## 同任务可比性

逐 seed 对照 `traditional_experiment_v1`：100×100 地图 JSON 和订单 JSON 完全一致；正式场景 JSON 的任务、端点及约束一致，v8 序列化时在每个场景上多写了一个 `road_map: null` 字段。移除该非语义字段后，十个 seed 的正式场景数据均一致。因此，本轮对照没有改变地图、订单或正式场景输入。

失败原因按任务范围：

- 订单 100 条：模型报告无合法路径 55 条；返回含非法移动的路线 13 条；JSON/路线结构解析失败 4 条；合法接驳点或地点解析失败 28 条（细分原因记录于审计 JSON）。
- 正式场景 50 条：可行类无路线 23 条；含非法移动路线 6 条；解析失败 1 条；按设计应失败的非法端点 10 条、不可达 10 条。
- 在全部 130 个传统组可行任务上，三种传统算法均能找到有效路线；因此这 130 条纯 LLM 失败不能解释为地图本身不可达。20 个预设非法端点/不可达场景则与实验设计一致。

19 条模型提议路线的完整假设能耗估算合计为 30.84645 kWh；首个违规动作前的合法前缀估算合计为 6.15930 kWh。没有路线步骤的 131 条响应记为“未提出路线/未估算”，不写成 0 kWh。两项路线能耗都是基于模型提议的事后估算，不是车辆实测消耗；完整违规路线估算不计入有效路线能耗或电费。

## 结论边界

这一轮 graph-only 输入下没有产出合法路线。对比旧版 v7，本轮没有越界动作，但仍出现逆单行方向；路线提议数量也明显不同，因此不能只按违规总数宣称路线能力提升。逐步掩码和更明确的边界规则没有让纯 LLM 路线生成达到可用结果。20 个预设不可行场景应与 130 个传统组可行任务分开报告。本结果不支持纯 LLM 路线质量或 Agent 优势结论。
