## 1. 结论与边界

这条流程可以接入当前路线层。保留现有 100×100 合成有向道路图、R0/R1/R2 传统路线结果和已有纯 LLM 诊断结果，另增一个“围栏内热度站点—有向 Link”路线实验分支。新旧结果回答的问题不同，不能直接合并成同一张方法性能表：旧结果是全图/局部节点图搜索，新分支检验围栏裁剪、站点点到路段绑定和 Link 级路线搜索。

可迁移的是处理机制：固定围栏 → 按热度筛站点 → 站点匹配到有向 Link → 形成围栏候选路网 → 求解并验证合法 Link 序列。原始内部站点、围栏和道路数据不作为实验输入。当前工作区中未找到用户提到的 `fence10089_B_common192_input_20261019/` 目录，因此不能声称已读取或转换其中的数据。

本方案属于路线层，不增加动态派单、车队再平衡或真实道路部署主张。真实交通信号配时和观测拥堵也不在此方案里；先复用现有仿真中的固定信号延迟与分档拥堵成本。

## 3. 合成数据的构造

1. **固定底图。** 复用现有 100×100 地图和同一组随机种子。把每条有方向的 `Edge` 当作一个有方向的 Link；双向道路仍是两个有方向 Link。围栏多边形、`fence_id` 和版本在每个种子生成后冻结，同种子下所有方法完全一致。
2. **生成站点。** 在围栏内合法道路上生成坐标位于路段内部的站点；每个点使用不含 Link ID 的随机稳定 `point_id`。评估器私有记录保存生成点的真实 Link 和沿路段偏移量，规划方法看不到这些真值。点绑任务分为几何上唯一的普通点和邻近多条候选 Link 的歧义点；坐标扰动幅度、道路语义标签和候选集均由种子固定，标签明确标记为模拟属性。
3. **生成热度。** 先用独立随机种子生成预热需求，仅统计围栏内站点作为起点或终点的次数，形成 `bubble_heat`。热度生成样本不再作为路线评测任务，防止把测试任务信息泄漏到热点选择中。筛选阈值或 Top-K 数在运行前冻结；每个方法读取同一份筛选后的站点表。
4. **点绑 Link。** 规划输入提供站点坐标和候选路段几何/方向，不提供 `ground_truth_link_id`。确定性基线使用最近合法有向 Link 规则；Agent-readable 组可结合 Link 名称/类别、围栏关系、邻接方向及站点语义证据返回候选。所有候选均由本地匹配器和验证器审计。
5. **生成任务。** 从冻结后的站点集合构造相同的起点—上车点—下车点任务；优先沿用路线层既定的精确/语义任务比例和随机种子。加入边界、绕行、单行约束、不可达等结构案例。不可达案例仍保留在分母中，不能在生成后按某一方法可达与否筛样本。

`point_id` 必须是不透明 ID。如果把真实 Link ID 编入对方法可见的点 ID，点到 Link 匹配会变成读取答案，不再是被测能力。围栏筛站、点到 Link 匹配、路线搜索三个阶段应分别保存状态，方便区分站点被筛掉、无法匹配、输入子图断连和搜索失败。

## 4. Link 级路由和成本

把 Link 作为搜索状态；当前 Link 的合法后继来自 `out_link_ids`。路线是有序 Link 序列，验证器检查相邻 Link 的终点/起点连续、方向合法、转向允许、围栏约束满足及最终位置正确。若站点位于路段中段，起步/结束成本只计对应的路段剩余比例，不能把站点直接吸附到最近节点后造成跳跃或反向通行。

围栏边缘使用冻结的边界策略：默认只允许围栏内 Link；若为了连通而加缓冲 Link，必须在所有方法共用的输入包中标出，且单独记录围栏外行驶距离/时间。不得让某个方法自行扩展边界。

先复用当前统一路线成本：道路通行时间由长度、基础速度、拥堵倍率和固定信号延迟计算；能耗继续由既有评估器按路线重新计算。热度只用于固定站点集和任务抽样，不在路线规划过程中被当作拥堵或时间真值。

## 5. 对照组

### 主方法

- **L0：几何点绑 + Link-Dijkstra。** 用冻结的最近合法有向 Link 规则匹配站点，再在围栏 Link 图上运行 Dijkstra。另用独立评估器的真值绑定重算参考最优代价，二者分开报告。
- **L1：几何点绑 + Link-A*.** 使用与 L0 相同的点绑结果、图、权重和验证器；启发式必须是可证明不高估剩余时间的下界。
- **L2：纯 LLM Link 路线。** 读取冻结的普通有向 Link 表和统一任务，自行返回点到 Link 候选和有序 Link 路线；本地独立校验，不补路、不静默替换模型答案。
- **L3：Agent-readable Link 工作流。** 按版本化 Link 特征协议查询围栏、站点、Link 属性、`in/out` 关系及道路状态；LLM 返回点到 Link 候选与依据，再调用冻结的 Link-A* 路线模块，最后通过相同验证器。

### 必要消融

为了把“地图表达方式”的效果与“路线算法”的效果拆开，增加 **L3-topology-only**：保留 L3 的模型、查询次数、Link-A* 路由器、输出 schema 和验证器，仅去掉语义名称/类别与站点—Link 语义关系；地图几何、有向拓扑、围栏、合法性、单行/转向约束、速度、拥堵、信号延迟、热度值及单位均保持一致。L3 与 L3-topology-only 的差异才用于解释 Agent-readable 语义关系带来的变化。L0/L1 与 L2/L3 的整体对比用于报告方法差异，不单独解释为地图表示的因果效应。

所有方法共享地图、围栏、点坐标、热度值、任务、道路成本、硬约束及随机种子；只有明确设计的可见性或方法模块不同。真值 Link、真实端点和参考最优成本只进入独立评估记录。

## 6. 评价指标

- **围栏和热点阶段：** 筛选点数、热度分布、围栏内/外 Link 数、过滤后可达点比例。
- **点绑 Link 阶段：** Top-1/Top-k 命中率、横向投影误差、方向不兼容率、无法匹配率和歧义候选数；按唯一点/歧义点分层。
- **路线阶段：** 有效路线率、可达任务覆盖率、Link 连续性错误、单行/转向违规、围栏越界、端点绑定偏差、路线距离/时间。分别报告“方法选中端点下的实际路线代价”和“真值端点下相对 Dijkstra 的路线代价差”，避免把点绑错误和路径搜索差异混在一起。
- **资源阶段：** 地图查询次数、LLM/API 调用、输入输出 token、响应/计算时延和失败分类。
- **样本和不确定性：** 按种子、围栏、任务类型分别列出分子和分母；报告均值、标准差和分位数。报告真实或模拟数据的来源类型，不把模拟热度/拥堵称作实测结果。

## 7. 分阶段接入

1. **离线结构预检：** 选择 seed 0 的一个固定围栏，导出 Link、站点和任务输入包；核对 `in/out` 邻接与原始有向边一致，所有站点点绑候选可追溯，围栏边界和真值隔离有效。
2. **传统算法验证：** 仅运行 L0/L1，和现有节点图路线成本逐例核对；修复 Link 连续性或部分路段计费错误后再扩大到 10 个种子。
3. **地图表达消融：** 离线运行 L3 的程序部分和 L3-topology-only，固定所有输入字段及路由器。
4. **模型阶段：** 先完成零网络调用的 prompt/schema/token 预检。任何新的付费 API 或账户额度调用都需依据当时有效的授权单独执行；本方案本身未发起模型调用。
