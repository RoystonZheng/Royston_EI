## EV v2 计算与计费

`route_experiment/energy_model.py` 按纵向动力学积分车轮功、推进效率、再生效率和辅机耗电。路段/轨迹净能耗为推进耗电减再生能量，再加辅机能耗；模型允许净能耗小于零。费用函数不把负净能耗转成负电费，而在每条实际路线腿边界将计费能耗置为 `max(net_kWh, 0)`。分段成本函数先在段内汇总带符号能耗再计费，并同时保留净能耗、计费能耗与费用基准，避免跨段再生能量抵消。

Porto SUMO runner 对实际完成的车辆路线腿使用该规则。电价按实验冻结值 €0.30/kWh 作为情景代理，并另做 €0.20/€0.40 敏感性值；不代表市场结算。乘客票价、车辆折旧、维护、保险、税费等未完整计价；Codex CLI 也未报告账户实扣，模型调用标准费率估值与欧元电费代理分币种记录、不能直接相加。因此不能宣称完整运营利润或全口径总成本。

## Porto R2 的共享 Link、决策和实际运行

零调用预检 `porto_r2_complete_energy_decision_preflight_20261027_v1` 记录共同图 SHA-256 `9811d6509608788e598e1a76861bb9bc37b0898d744bc01eed2bf7fefb346017`，并确认图在方法启动前可用。传统路线使用时变 Dijkstra 搜索；LLM prompt 带入同一 Link 图，并在动态合法路网、信号程序和交通快照上提出路线。模型路线须通过确定性方向/禁行/转向校验；随后本地按同一快照计算目标分数，只有严格优于共享 Link fallback 才保留。由此，静态 Dijkstra 图是共同基准和兜底，不是限制模型路线的必经路线。

决策与执行是分开的：计划路线依据发车时的交通/信号预测快照选择；之后 SUMO 中固定车辆按固定订单序列真实运行，信号随时间变化、车流及拥堵影响实际通过时间，实际时间和 EV v2 电耗用于结果评价，不回写成规划时已知信息。当前目标按两个独立实验单元比较最快时间与最低预测能耗，尚无获准的单一“省时或省钱”净经济综合排名。Porto R2 time-money v2 gate 已将后者阻断：票价和完整候选路线池缺失，不能把缺失费用当零或把不完整候选集用于综合评分。

当前修正后的传统矩阵 `porto_r2_traditional_20261027T025652Z` 使用上述 runner / route-problem 代码 SHA，并在 manifest 中记录共同图已在方法开始前载入。审计时它仍在运行，不能引用未终态格作为完整矩阵结果；以其最终 ledger、逐格 summary、validator、SUMO 轨迹和账单字段的后续核对为准。

## 通用决策函数的适用边界

`route_experiment/decision.py` 中 `score_route_candidates` 会先排除违反硬约束或缺少时间/费用的候选，再在同一候选集做 min-max 归一化并按冻结权重排序。它允许负的净经济成本，但要求已知金额和明确价格基准。此函数不是 Porto R2 正式 FASTEST/LOWEST_ENERGY 路由器，也没有自动识别或强制纳入 Dijkstra fallback；调用者若要按该函数排序，必须把共享兜底和所有预先声明的合法候选共同放入同一候选集，并为每项提供相同口径的真实/预测时间和完整费用。当前 Porto gate 不满足这些条件，故不得将该函数输出用作 Porto 正式决策结论。

代码级检查另以直接断言核对了负净能耗截零、正净能耗计价和多段汇总；未运行全量测试套件。
