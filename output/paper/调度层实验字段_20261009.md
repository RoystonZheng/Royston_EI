# 调度层实验字段定义

日期：2026-10-09  
状态：首版字段定义。  
适用范围：10 辆车、1 小时、100 个动态订单的一对一无人网约车调度实验。  
前置条件：路线层已经为车辆—订单组合生成统一路线候选表。

## 0. 字段使用规则

- **必填**：每条记录都必须有值。
- **条件必填**：满足条件时必须有值；不满足时写 `null`。
- **可空**：字段保留，但当前方法或场景可能没有值。
- 数组没有内容时写 `[]`，对象没有内容时写 `{}`；不要省略字段。
- 时间统一使用仿真开始后的秒数；距离使用米；能耗使用 kWh；费用使用统一货币单位。
- `null` 表示不适用或尚未发生，`0` 表示确实为零，二者不能混用。
- 所有方法读取相同的完整输入包，并转换为相同的输出包。
- 300 秒是订单产生至车辆到达上车点的最大等待硬约束；180 秒是车辆到达后乘客未上车的取消阈值。
- LLM 不得修改硬约束、已有服务承诺、车辆数量或一对一规则；程序和数学优化器负责最终校验。

## 2. 空间热点记录 `Hotspot`

三个热点在场景开始时固定：高密度热点面积最小，中密度居中，低密度最大；三个热点被抽中的概率相同，热点内部随机选择合法上车点。

| 字段 | 类型 | 含义 | 必填性 |
|---|---|---|---|
| `hotspot_id` | string | 热点编号 | 必填 |
| `density_label` | enum | `high`、`medium`、`low` | 必填 |
| `center_node_id` | string | 热点中心节点 | 必填 |
| `legal_pickup_node_ids` | array[string] | 热点内合法上车点 | 必填；至少一个 |
| `area_size_m2` | number | 热点面积 | 必填 |
| `legal_pickup_node_count` | integer | 合法上车点数量 | 必填 |
| `sampling_probability` | number | 热点抽样概率，三个热点相同 | 必填 |
| `map_boundary_valid` | boolean | 热点是否在地图边界内 | 必填 |

## 14. 方法与字段适用关系

| 方法 | 情境函数 | Agent筛选 | LLM候选反馈 | 数学优化器 | 不适用字段处理 |
|---|---:|---:|---:|---:|---|
| D0 逐订单最近可行车辆 | 否 | 否 | 否 | 否 | 函数、Agent、LLM、优化器耗时写 0；相关对象写 `null` 或 `{}` |
| D1 集中式数学优化器 | 否 | 否 | 否 | 是 | Agent 和 LLM 字段写 0 或 `null` |
| D2 Agent+优化器 | 人工/固定 | 是 | 否 | 是 | LLM 反馈字段写 0 或 `null` |
| D3 Agent+LLM函数+优化器 | LLM函数 | 是 | 否 | 是 | 候选反馈字段写 0 或 `null` |
| D4 Agent+LLM函数+LLM反馈+优化器 | LLM函数 | 是 | 是 | 是 | 无特殊空字段 |
| D5 纯LLM派单 | 否 | 否 | 可选 | 否 | 函数、Agent、优化器字段写 0 或 `null`；仍经过统一验证器 |

## 15. 优化器最少读取字段

优化器主要读取以下字段，不直接依赖自然语言理由：

- `vehicle_id`、`order_id`、`candidate_type`；
- `route_reachability`、`route_validation_status`；
- `next_order_wait_sec`、`max_wait_slack_sec`、`handoff_ok`；
- `current_commitment_impact`；
- `hard_constraint_pass` 或等价硬约束检查结果；
- `incremental_cost_vector`；
- `estimated_violation_risk`；
- 当前车辆占用、下一订单预留和订单状态。

LLM 理由、原始输出、提示词和函数生成记录用于审计、错误分析和消融，不直接替代程序校验。
