# 调度层 Agent 多月正式实验方案

日期：2026-10-24  
状态：输入包、训练与留出运行已完成；正式结果审计为 89/90 个有效配对单元，1 个 D7 回放因无有效策略不可用。  
证据边界：本文保留预先冻结的方案，并附已完成模拟的审计结果。结果只支持选定 TLC 完成行程代理窗口与合成车队下的描述性比较。

## 1. 研究问题与方法组

主问题：在统一的订单、车队、区域成本代理、硬约束和校验器下，集成的 D8 调度工作流与现有派单基线相比，服务表现和计算/资源成本如何变化？

| 方法 | 用途 | 关键机制 |
|---|---|---|
| D0 | 简单规则参照 | 贪心候选匹配 |
| D1 | 数学优化参照与 MLP 标签来源 | 确定性全局优化器 |
| D2 | Agent 工作流参照 | Vehicle Agent + 优化器 |
| D5 | 纯 LLM 参照 | Codex CLI 直接给出派单建议，硬约束由程序校验 |
| D6 | LLM 策略消融 | Agent + Codex 生成情境函数参数 + 优化器 |
| D7 | 容量保护消融 | D6 + 最大匹配容量保护 |
| D8 | 主方法 | D7 + D1 模仿学习 MLP 排序 + 优化器 |

预期贡献是可检验的工作流与约束处理设计，不预先宣称多 Agent、LLM 与优化器结合或最大匹配保护为首创。新颖性须在相关工作中单独比较后再判断。

## 2. 数据与样本

- 来源：NYC TLC 2024 High-Volume FHV 月度 Parquet、官方 taxi-zone lookup 和区域多边形；原始文件 SHA-256 按数据集清单核验。
- 代理对象：已匹配并完成的行程作为订单到达代理。它不包括拒单、未服务请求或真实车队轨迹。
- 时间窗：每窗 5 分钟、晚上 20:00–23:59。先按时间、共享订单标记、行程字段和区域几何筛出可复现记录，再对每个服务日选择订单最多的窗口；同数时选较早窗口，至少 250 单且覆盖 12 个指定曼哈顿上车区。
- 训练：2024 年 1–2 月，各月在日最大窗口订单量分布中选 q10/q30/q50/q70/q90，共 10 个窗口。每个窗口以 F1 车队完整运行 D1，按候选边冲突关系生成 D1 模仿标签。
- 留出：2024 年 3–12 月，各月选 q25/q50/q75，共 30 个不同服务日。训练和留出订单 ID 不重叠；日期也不重叠。
- 车队：F1/F2/F4 分别包含 12/24/48 辆合成车辆，初始位置在 12 个上车区按固定规则布置。每个日期/车队只使用 seed 0，一次模型运行；不把同一订单窗口的多 seed 当成独立需求样本。
- 空间缺失：官方多边形未覆盖的端点在选窗前排除；不将其记作失败订单。当前冻结包在所选 40 个时间戳中共排除 2,638 条其他合格记录。
- OD 成本：使用既有训练期观测 zone OD 中位数。所需 1,882 对中，1,881 对有观测值；161→30 以官方区域多边形质心、1.3 detour、5 m/s 估算，并在矩阵行标记为 `taxi_zone_centroid_fallback_v1`、`source_trip_count=0`。成本是区域级代理，不是道路 ETA。
- 冻结包：`outputs/dispatch_layer/nyc_tlc_hvfhv_2024/dispatch_formal_multimonth_v1/benchmark_manifest.json`。

## 3. 运行协议

所有方法逐个使用相同的冻结 scenario、orders、区域成本矩阵和相同 `scenario_fingerprint_sha256`。每个模拟只看到当前已到达订单；一车一单、最大接驾等待和已有车辆承诺仍由程序硬约束与独立 validator 管理。

D8 在每个日期/车队单元执行一次 Codex 情境策略调用。若返回有效、被接受的策略参数，则 D6/D7 回放相同响应；回放必须有逐字节一致的 prompt、原始 JSONL、最终 JSON 和无新增调用记录。若 D8 没有可接受响应，D8 按实现记录回退；D6 执行其自身预定的一次 live run，D7 回放 D6 的有效响应。D5 在每个存在硬可行候选的调度轮次独立 live 调用。正式留出 live 阶段前先完成 D0/D1/D2 确定性全量预检，并以逐轮审计得到 D5 请求量基线；预检不改变冻结场景、指标或方法。所有 live 模型调用零自动重试，原始 Codex JSONL、prompt、响应和执行日志均保留。

MLP 只在 10 个早期训练窗口的 D1 选择结果上拟合。为控制高频候选快照的存储量，D1 标签文件保存每轮硬可行候选的训练特征、车辆/订单/候选 ID、D1 选择 ID 和完整逐轮校验摘要；不保存重复的完整仿真状态快照。候选集合仍由同一 D1 仿真过程生成。模型版本、特征顺序、训练 seed、轮次、训练源哈希和模型 SHA-256 写入训练报告。训练命中率只是 D1 标签拟合诊断，不作为策略效果。

## 4. 指标与比较

### 主要结果

- 每个窗口的已服务订单数与服务率；解释范围仅限已完成行程代理和当前合成车队场景。
- 已服务订单平均及 P95 接驾等待；同时报告未服务/过期单数、硬约束错误和 commitment violation。

### 机制与资源

- 空驶距离与区域级能耗代理；
- 调度轮数、每轮候选量、Agent/情境筛选前后候选数、MLP 剪除、最大匹配容量恢复、回退次数；
- 优化器、决策和模型延迟；Codex 调用数、输入/缓存/输出 token、无效或拒绝响应。

Codex JSONL token usage 用于用量审计。公开费率折算只列估算值；Codex 账户实际扣费不能从 token 日志推得。D6/D7 对已回放的同一次调用不重复计费。

## 5. 统计口径

- 主比较对象：D8 对 D2；组件分析：D8 对 D6/D7；参照比较：D8 对 D0/D1/D5。
- 先分别报告 F1、F2、F4 的 30 个按日期配对差值；汇总区间时以 service date 为 cluster，同一日期的三种 fleet 一起抽样，避免将 90 个单元误当成 90 个独立需求日。
- 报告各方法在 30 个日期窗口中的差值分布、均值/标准差和日期簇配对 bootstrap 95% 区间。日期是按月份需求分位选出的固定留出集，因此不据此做纽约市总体假设检验；若后续补充 p 值，只作为选定窗口上的探索分析，并对同一指标下的方法比较做 Holm 校正。
- 月份内的 q25/q50/q75 选择是分层样本，不是从全部 NYC 行程中简单随机抽样。因此统计区间描述所选窗口的跨日变化；不得据此声称纽约全市总体效果。
- 主分析包含配置的端到端运行结果，并另行报告模型接受率和回退率；若有无效模型响应，不删掉失败记录后再宣称成功率。另做仅接受 Codex 策略参数的敏感性分析。

## 6. 完成门槛

1. 训练与留出订单/日期隔离，case 文件哈希通过。
2. 每个方法的订单、车队和矩阵哈希一致；模型输出、usage JSONL 与结果记录逐项对账。
3. 对所有完成模拟逐轮核对 validator、硬约束、一对一分配、已有承诺和 D8 最大匹配容量保护；回放组 prompt 哈希一致且新增请求为零。
4. 报告所有缺失、失败、模型拒绝、程序回退、未知用量和日志损坏；不得静默重跑付费模型调用。
5. 运行覆盖全部 30 个日期 × 3 个车队 × 7 个方法后，生成可复现 CSV、审计 JSON 和论文结果草稿。若有单元无法满足门槛，结果标为部分完成，并说明可支持的结论范围。

**最终审计（2026-10-25）：**30 个留出日期 × 3 种合成车队共 90 个计划单元均已尝试。D0/D1/D2/D5/D6/D8 各有 90 份完整结果，D7 有 89 份；4 月 11 日 F2 的 D8 与一次 D6 补充调用均返回无效策略参数，因此没有可用于 D7 的接受策略。按零重试规则保留该缺项。结果文件 629/630；89/90 个单元的全部方法结果完整、输入哈希一致且逐轮 validator 通过。D8 对 D2 的平均接驾等待差为 +1.72 秒（日期簇 bootstrap 95% CI：+0.68 至 +2.80），服务率差为 -0.000043（95% CI：-0.000108 至 0），P95 等待差为 +0.31 秒（95% CI：-1.70 至 +2.17）。因此当前结果没有显示 D8 带来服务表现提升；统计范围限于这些按分位选择的日期窗口和单次 seed。

唯一 Codex CLI trace 审计到 1,639 个已完成 turn：D5 1,541 次、D8 90 次、D6 补充调用 8 次；总输入 token 30,973,582（其中缓存输入 19,395,968）、输出 token 252,047、总 token 31,225,629，JSONL 损坏行 0。D5 有 1,526 条接受策略记录和 15 条错误/无效响应；D8 有 82 条接受策略记录和 8 条无效参数；D6 有 89 条接受记录和 1 条无效参数。Token 追踪不是实际账户账单证明；实验后账户周使用率 22% 是包含其他活动的全局快照。

审计产物位于 `outputs/dispatch_layer/nyc_tlc_hvfhv_2024/results/dispatch_formal_multimonth_v1/`：`run_audit.json`、`usage_audit.json`、`method_summary_by_fleet.csv`、`paired_differences.csv`、`paired_statistics.csv`、`comparison_report.md` 和 `实验结果摘要_20261025.md`。数据仍是已完成 TLC 行程代理、区域 OD 成本代理和合成车队场景，不代表 NYC 真实派单或真实车辆轨迹。

## 独立种子补充实验（2026-10-25，原冻结结果之后追加）

首轮正式批次每个日期/车队只运行 seed 0，无法估计同一需求窗口下模拟及 Codex 输出的运行间波动。为补足这一点，追加 seed 1–4；原 seed 0 文件和审计不修改。五个 seed 使用相同的冻结场景、订单、区域 OD 成本矩阵、方法集合、validator、Codex 模型与 D1 标签训练出的同一份 MLP 检查点；不按留出结果重新训练模型。每个 seed 仍覆盖相同 30 日期 × 3 车队单元，并让同一 seed 下的各方法共享模拟随机种子，以保持配对。

补充批次分别写入 `outputs/dispatch_layer/nyc_tlc_hvfhv_2024/results/dispatch_formal_multimonth_replicates_v1/seed_1/` 至 `seed_4/`；每个 seed 有单独 progress ledger、执行日志与 manifest。结果保存在对应 `evaluation/` 中，文件名保留 seed 值。Codex 调用仍零重试：遇到失败、无效响应或中断时保留原始 trace 和缺项，不重复同一 seed、同一日期/车队、同一方法的 live 调用。分析按 service date 做 cluster bootstrap，并把该日期下所有 fleet 与 seed 一起重采样；多 seed 增加的是同一批选择日期的运行重复数，不增加独立需求日期数，也不支持 NYC 全市总体推断。

合并统计在日期和 seed 两个维度做成簇 bootstrap：每次重采样保留一个日期内的全部车队结果，并重采样整个 seed 下的日期结果；日期内先等权汇总可用 seed，每个日期再等权进入总体效应。这样同时反映日期间差异与重复运行差异，不让少数完整单元更多的日期获得额外权重。

主效应按 D8 与每个参照方法分别做完整性、seed、输入哈希和 validator 配对核验，并保留该配置的策略拒绝/回退作为 intention-to-treat 结果；一个 D7 缺项不删除同格仍完整的 D8-D2/D5/D0/D1 比较。D8 对 D6/D7 的组件归因另限制在 D8 策略被接受、D6/D7 与 D8 prompt 哈希一致且确实回放、无新增调用的子集，和总体配置结果分开呈现。

补充一项纯离线神经网络诊断：把冻结 MLP 应用于留出日期 D1 优化器生成的候选图，严格复用训练时同车/同订单冲突负例定义、SHA-256 稳定排序和每正例最多 64 个负例，测 pairwise label fidelity，并报告每个 D1 已选候选在同车可行候选中的 MLP top-1 一致率。该分析检查 MLP 对 D1 标签的留出泛化，不调用 LLM、不改变调度方法比较，也不等同于乘客服务提升；按日期与 seed 汇总区间。
