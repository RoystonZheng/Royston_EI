## 输入成本与两项建议

v9 的 28 个已完成 turn 共记录 473,061 输入 token、10,122 输出 token；52,992 cached input 是输入 token 的子集。平均每个已完成调用约 16,895 输入、362 输出，记录的 CLI 时延总和约 361 秒，平均约 12.9 秒。Codex CLI 未报告账户实际扣费，两个中断调用的 usage 也未知。

### 1. 精简地图输入

该建议已经部分落地：`r4-step-v3` 用紧凑有向成本网格代替逐节点、逐边 JSON，并有全图语义等价审计。剩余主要开销不是每格编码仍可缩短一点，而是每次独立请求都重发完整紧凑地图。仅按当前平均值估算，剩余 53 步至少还需约 895,000 输入 token、约 11.4 分钟的已记录模型时延；这是外推，不是实测，也不含未决请求成本。

持久会话可以减少重发上下文，但它会改变当前 `ephemeral_per_request` 调用条件；改为一次输出多个动作也会改变“一次只提议一步”的处理组。两者都应另立协议版本，不能悄悄改写 v9。

### 2. 外置确定性路线校验

这项安全措施也已经落地：本地程序根据真实有向出边、已访问点、取送顺序、剩余可达性和动作预算生成方向 schema；模型响应返回后，再独立校验有向边、连续性、边界、重复访问、端点顺序及剩余可达性。只有校验通过才推进路线状态。模型自检不能覆盖程序判断；当前 56 步没有非法动作被接纳。

当前校验器不是提供给模型调用的 function tool，而是模型响应之后的本地准入门。把它改造成模型可调用工具并不会修复本次进程中断，还可能改变工具使用条件和 token 开销；只有把“模型在规划时主动调用校验器”作为新实验变量时，才有必要另行设计。

## 对“CoT 分步生成”的判断

当前提示要求模型先考虑剩余完整路线、每次只提交一个方向，并填写结构化自检；不要求输出长篇自由推理。由于每次请求都是独立 CLI 会话，模型不会保留上一步的隐藏推理，只会收到当前完整地图和压缩后的路线状态。因此这不是一次连续的 CoT 会话，而是每步重新规划。增加长篇思维链不会解决停机或重复传图；应继续以可审计动作、结构化自检和本地程序校验为准。

## 后续边界

保留 v9 为**单任务、未完成、合法前缀 pilot**，不记为模型路线失败，也不记为完整路线成功。当前有效停止指令不允许继续请求。若以后续跑，应先在既有实验方案下冻结单任务的请求/时间/费用熔断；若采用持久会话或多步段落输出，应作为新版本单独预注册和比较，不把两种协议的数据混合。
