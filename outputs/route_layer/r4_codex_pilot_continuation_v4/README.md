# Codex 独立 8×8 路线试跑 v4

## 结果

本轮从 v3 最后一处已接纳节点 `node_0_4` 继续，地图与任务保持不变：`grid-8x8-seed-0`，64 个节点、205 条有向边；起点 `node_0_5`，上车点 `node_1_2`，下车点 `node_6_2`。

模型在 8 次新请求内先到达上车点，再到达下车点。8 次动作全部通过动态 JSON Schema、本轮五项模型自检和本地确定性有向边/顺序/边界校验；0 工具事件、0 重试、0 非法移动。最终完整路线共 31 条有向边、3,100 米，仿真行驶时间 379.514 秒，按 `energy_v1` 估算 0.57745 kWh。该结果只说明这一个冻结任务完成，不表示路线最优，也不代表正式多种子结果。

v3 曾在 `node_0_4` 收到 `S`，但 `not_revisited=false` 与本地“目标节点未访问”事实冲突，因此当时没有执行。v4 没有重放那次拒绝动作；改用显式节点访问列表和正向 `target_node_is_new` 自检字段，从同一合法节点重新发起请求。v4 第 1 次再次选择 `S`，五项自检和本地校验均通过。一次成功不能证明协议修改是唯一原因或能普遍解决模型自检错误。

## 方法边界

每次请求只让 Codex CLI 选择当前一步，程序用动态 schema 限制可选方向，并在执行前作确定性硬校验；程序未用 Dijkstra/A* 替模型生成路线或修补模型动作。程序会用剩余最短步数下界过滤无法在动作预算内完成任务的方向，因此本试跑是“LLM 逐步选边 + 本地可行性过滤/硬校验”，不是无约束的纯 LLM 路线生成，也不是传统算法基线。v4 的 8 次续跑里，7 步 schema 只给一个允许方向，1 步给两个方向；因此它验证了受约束的逐步请求和完整执行链，模型在这段续跑里的选路空间有限。路线质量和最优性尚未与基线比较。

## Token 与费用

v4 的 8 次调用合计 78,820 输入 token（其中缓存输入 8,320）和 3,346 输出 token，共 82,166 token。按 GPT-5.6 Luna Standard 官方费率折算为 0.457040 Codex Standard credits 等值、$0.01828160 API 标价等值。Codex CLI 没有报告实际账户账单或订阅额度扣减；这些是费率卡等值，不是实际账单。

将初始 smoke 与 v1–v4 续跑合并，累计 32 次模型请求、384,526 输入（缓存 8,320）和 31,516 输出，共 416,042 token；累计 2.830670 credits 等值、$0.11322680 API 标价等值。历史 v3 被拒绝提议未执行：实际车辆能耗 0 kWh；如执行该边则估算 0.018 kWh，该估算不计入路线实际能耗。

费率来源：[Codex 官方价格说明](https://developers.openai.com/codex/pricing)、[GPT-5.6 Luna API 价格](https://developers.openai.com/api/docs/models/gpt-5.6-luna)。
