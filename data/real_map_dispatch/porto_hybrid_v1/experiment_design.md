# 基于真实路网与仿真交通的无人网约车派单实验设计

**版本：** 2026-10-22 v1  
**状态：** 新增研究设计稿；数据包建设与实验均未完成。本文件与既有路线层、调度层设计并行保存，不覆盖其内容或结果。

## 1. 研究目标与范围

本实验拟在真实地理道路网络上构建可重复的仿真派单场景，研究车辆 Agent 对地图和时变道路状态的读取方式，是否会改变路线成本判断及全局派单结果。实验采用公开出租车轨迹生成需求分布代理，采用 OpenStreetMap（OSM）建立有向道路网络，并用 SUMO 生成信号配时、背景车流和拥堵情景。

研究对象仍是一对一动态无人网约车：车辆每次最多服务一个乘客订单；车辆 Agent 评估其可服务订单及其候选路线；全局数学优化器选择车辆、订单和路线。该分支增加真实地理路网和仿真交通约束，不改变既有 100×100 合成地图路线实验，也不将其结果与真实路网分支混合计算。

### 研究问题

- **RQ1：** 在候选路线、底层道路事实和模型相同的条件下，类型化 Agent-readable 地图是否改善 LLM 对路线时间和道路风险的估计与排序？
- **RQ2：** 将车辆 Agent 的路线成本估计交给全局优化器，能否在统一硬约束下改善派单等待、服务率和行驶资源成本？
- **RQ3：** 信号等待和不同拥堵强度是否会改变候选路线排序及车辆—订单匹配结果？

这些是待检验问题，不预设 Agent-readable map 或 LLM 一定优于传统方法。

## 3. 数据集构建流程

1. **获取与校验来源。**已从 Figshare CC BY 4.0 记录下载描述 Porto 全年出租车轨迹的压缩文件，镜像 MD5 与 ZIP CRC 已通过，端点热度与 OD 网格表已生成；其与当前 UCI 下载文件的精确内容等价性和 1 行计数差异仍待确认。候选 OSM 快照也已保存查询文件、时间戳、范围、哈希和 ODbL 归属说明；围栏正式冻结前仍需完成道路/转向限制校验。
2. **按时间切分轨迹。**按行程开始时间排序，建议 70% 作为需求热度训练期、15% 作为仿真需求校准期、15% 作为测试期。冻结围栏、热点、请求抽样规则和参数后，测试期不参与地图或模型调参。
3. **筛选围栏和热点。**在 Porto 候选城区以预先指定的网格聚合历史起终点热度，按道路连通性、可服务热点数和地图规模门槛筛选区域；确定后冻结 `fence.geojson` 与区域 ID。每个热点保留起点/终点计数、统计时间段和空间网格。无官方站点标签时称“热度候选点”或“虚拟上/下车点”。
4. **构建有向图与站点绑定。**将确认可供机动车通行的道路拆为有向 Link；按 OSM 单行、机动车通行和转向限制建立合法连接。`highway=service` 不直接整体纳入主路由图：回查 `service`、`access`、`motor_vehicle` 等原始 Way 标签，默认排除 parking aisle、driveway 等内部通道作为穿行路线，需时另做含/不含服务道路敏感性分析。对每个虚拟站点保留多个近邻 Link 候选及匹配置信度；评估真值与模型输入分离，避免把 GPS 噪声或多义道路误判为模型错误。
5. **生成车辆、订单和背景车流。**订单到达时间与 OD 由历史分布分层抽样；车辆位置、可用时刻和仿真车队规模由固定随机种子生成。背景交通流由校准期 OD 分布生成，低、中、高三个强度共用相同 OD 结构，只改变冻结的出发率参数。
6. **生成候选路线和交通成本。**对每个可行车辆—订单组合，传统有向路由器生成固定的 K 条候选路线，首轮建议 K=5；候选集由自由流时间、距离和路线差异约束共同产生，再去重。每个候选方案至少含“车辆当前位置→上车点”与“上车点→下车点”两段。SUMO 在固定交通种子、信号方案和背景需求下估计两段旅行时间、红灯等待、排队损失和行驶距离。
7. **冻结共享输入。**归档地图、围栏、热点、车辆/订单、候选路线、SUMO 场景、成本字段、随机种子和独立校验器的版本及哈希。所有方法读取同一份方法中立候选表。

### 混合订单端点与道路特征点

订单端点沿用既有路线层用户确认的混合比例：**70% 精确候选点任务、30% 语义/模糊地点任务**。对本真实地图分支作如下可复现实例化：

- 精确组每单的上车点和下车点均从冻结的 30 个热度候选点抽样；上车按历史上车计数加权，下车按历史下车计数加权，并尽量避免同一候选点自环。
- 模糊组每单仅有一个模糊端点，取/送端各以 50% 概率成为模糊端；另一端仍从候选点池抽样。模糊端点由固定种子在 OSM 道路特征附近的非 `service` 道路几何上重新采样，不维护一组固定模糊站点。
- 当前地图原型把道路特征分成两类：①非 `service` Way 几何中被至少两条不同 Way 共享的顶点，作为“道路交点候选”；②OSM `traffic_signals` 点。模糊端点从交点的相邻线段或距离信号点不超过 35 m 的最近线段上随机取样，沿该几何距特征位置最多约 55 m；端点周围画出约 35 m 不确定范围。该距离是原型参数，不是 GPS 误差实测或已冻结实验参数。
- 当前简化视图可推导出 1,172 个共享顶点交点候选，地图稀疏显示其中至多 90 个未与信号点重叠的代表点；418 个信号位置仍在独立图层显示。共享顶点计数依赖坐标按 1e-6 度归并，且当前展示数据未保留 way/node ID、bridge/tunnel 和转向限制；它只用于交互原型，不能代替正式 OSM 拓扑提取或交通信号受控连接真值。
- 生成器以地图快照、热点表、生成器版本、订单数和随机种子为输入。同样输入必须复现相同订单与端点。正式每种子 100 单时恰为 70/30；交互页默认展示 20 单（14/6），允许 1–100 单作预览，小样本比例按整数取整。
- 此订单模块仅生成空间 OD 端点，不提供请求时刻、车辆状态、候选 Link 或路径。正式仿真仍按本节步骤 5 从冻结的历史时间分布抽样请求到达时刻，并由传统有向路由器为模糊端点计算近邻 Link 候选、合法候选路线和成本；地图上的 OD 虚线不得作为路线距离或路线成本。

模糊端点的正式评估需独立记录 Link 候选召回/精度、候选集规模、匹配置信度、机动车通行合法性、OD 可达率及最终路线合法率；精确点与模糊点分层报告，不把地点定位困难误计为 LLM 路线搜索错误。所有方法共享相同生成订单、种子、特征点来源和独立地图匹配/路线校验器。

### 时间与交通耦合

首轮主实验采用**外生背景交通**：各方法读取同一仿真交通状态，派单结果不回写背景车流。这能稳定比较地图表示和派单策略。它检验的是给定仿真路况下的规划/派单，不声称车辆派单本身改变了城市拥堵。后续如有实现预算，可单独增加闭环 SUMO 回放，让被选车辆按派单路线进入仿真并反馈后续交通状态；闭环结果须另列，不能与外生交通结果合并。

## 5. 派单方法和 LLM—优化器职责

每辆车对应一个 VehicleAgent。LLM 仅为该车的可行订单—路线候选输出结构化成本判断，不直接决定全局匹配，也不能创造候选表之外的 Link 或路线。全局优化器读取所有车辆 Agent 的候选结果，处理车辆和订单之间的冲突并给出最终选择。此边界与现有研究架构一致。

### 方法组

| 编号 | 方法 | 作用 |
|---|---|---|
| D0 | 传统 ETA + 最近可行车辆贪心 | 基础调度对照；使用统一合法性和等待时间约束 |
| D1 | 传统候选路线成本 + 全局优化器 | 评估数学优化器相对贪心的作用 |
| D2 | VehicleAgent + 扁平道路记录 LLM + 全局优化器 | 与 D3 配对，测试普通序列化路网 |
| D3 | VehicleAgent + 类型化 Agent-readable map LLM + 全局优化器 | 主实验方法，测试显式拓扑、转向、信号及交通关系 |
| D4 | D3 消融：隐藏信号/拥堵状态或移除道路语义字段 | 分别测量交通状态和地图语义字段的增量作用 |
| D5 | SUMO 候选成本表 + 同一优化器 | 有限候选集上的成本参考上界；不作为可部署方法或 AI 效果结论 |
| D6（可选） | 纯 LLM 直接给全局匹配 | 仅作为诊断组，必须过相同候选 ID 和硬约束校验，不作为主要方法 |

D2 与 D3 使用同一 LLM 版本、提示目标、字段值、候选路线、上下文预算、输出 schema、优化器、验证器和随机种子，唯一主要变化是地图事实的组织方式。LLM 看不到 SUMO 对候选路线计算的最终真实仿真总成本；它读取道路属性和当前可见交通状态，预测候选 ETA/延误/风险。SUMO 仿真结果作为独立评估值，避免让 LLM 直接复述标准答案。

### 优化模型

以 (x_{v,o,r}\in\{0,1\}) 表示车辆 (v) 是否接受订单 (o) 并采用候选路线 (r)。优化器至少满足：每个订单最多分配一辆车；每辆车在同一时刻至多接受一个新订单（已有服务承诺仍按当前项目规则保留）；只选择候选表中可达且合法的路线；预计接驾等待不得超过 300 秒。乘客到达后 180 秒仍未上车的取消规则沿用既有调度实验，并由所有组共享。

采用词典序目标：先最大化硬等待约束内的服务订单数，再最小化总接驾等待，最后最小化空驶距离/能耗等资源成本。信号与拥堵影响进入路线 ETA；避免把同一延误同时计入等待和附加成本。D2/D3 的优化器使用 Agent 输出的 ETA/风险估计，D0/D1 使用传统路线成本，D5 使用 SUMO 测得的候选成本。所有最终路线重新交给确定性校验器和仿真评估器复核。

## 6. 实验设置与控制变量

### 主设置建议

- 每个场景 10 辆仿真车、100 个订单、1 小时订单窗口，10 个配对随机种子；正式规模在数据可行性预检后冻结。
- 每个订单的取/送点从冻结热点和历史 OD 分布抽样；订单到达时间按历史时段分布重放或 bootstrap。车辆初始位置和后续可用时刻由同一生成器产生。
- 每种子 100 个订单按 70% 精确候选点到候选点、30% 单端模糊道路特征点生成；模糊端点在交点/信号位置邻近道路几何上按种子随机变化，另一端来自相同候选点池。正式预注册时冻结道路特征提取版本、模糊范围、半径、抽样权重和订单文件哈希。
- 每个车辆—订单组合最多保留 5 个合法候选路线；K=3 和 K=10 用于候选集敏感性分析。
- 低/中/高三档 SUMO 背景交通，按相同 OD、车型和信号种子配对；信号时序显式记录为固定或感应式配置。
- 车辆每 30 秒或每个新订单到达时触发一次派单；触发间隔确定后各方法一致。具体更新频率在小规模预检后冻结。

### 动态信号—拥堵耦合设计

实验环境按秒推进，车辆进入路段后由 SUMO 的信号相位、背景车流、跟驰和排队共同决定路段旅行时间。每条受控转向在时刻 `t` 记录红/黄/绿相位、距下一次相位切换时间、排队车辆数、等待时间和仿真旅行时间；路段成本使用同一仿真时钟下的时间依赖值 `T_e(t)`。交通灯变化先改变可放行流量，形成或消散队列，再影响该路段与后续路线的旅行时间。模型或优化器在派单触发时只读取当时可观测的路网状态，不能读取未来相位或该候选路线的最终仿真旅行时间；选出的路线再由 SUMO 回放获得评估真值。

信号与路段的正式关联必须依据 SUMO 网络中 traffic-light system 控制的 connection/link index，而不能仅按地图上最近信号点连接。OSM 中的 418 个信号节点表示设施位置，不含真实配时；首轮使用可复现的固定相位方案作为明确标记的模拟设定，建议 60 秒周期、绿/黄/红 32/3/25 秒，周期偏移由信号 ID 与交通种子确定。另以 45 秒和 90 秒周期做灵敏度情景；这些均不是 Porto 实测配时。SUMO 每 1 秒更新仿真状态，每 5 秒采集一次状态供派单和 Agent 查询，统一写入 `source_type=simulated`、`sim_time_s`、`simulation_seed` 和 `traffic_program_id`。

本轮可视化内的 2,179 条 OSM 道路候选 Way 仍是简化筛选子集，其中 773 条 `highway=service` 已从普通道路改为独立虚线图层，可在界面开关。其子类型与机动车通行规则需回查原始 OSM 标签后才能决定是否进入正式路由图；它们当前不进入信号—拥堵动态演示。地图上另外 8/10 条拥堵示意路段按不超过 20 m 的信号点距离暂时配对，另 2 条保持无信号固定队列；这只是显示机制的临时近邻关联，不是路口控制关系真值。交互原型以 5 秒为步长，使用 60 秒周期（绿/黄/红 32/3/25 秒）、假设车流率和服务率计算 `T_e(t)=L_e/v_e+q_e(t)/μ_e+W_e(t)`；它只展示信号变化如何生成/消散队列并改变当前通行时间。原型流率、速度、相位偏移都是人为演示参数，正式实验用 SUMO 车辆穿越和受控连接输出代替，不能把原型时间当成观测或实验结果。

首轮预注册三类配对条件：①**静态路况**，将自由流/平均延误固定在整轮，作为传统基线；②**动态信号+队列**，按上述相位、需求和队列实时更新，作为主情景；③**动态交通信号消融**，仿真环境仍运行同一动态信号，但对 D3 隐去相位与排队字段，仅保留道路静态属性，用于测量地图对动态交通状态的可读性贡献。每个条件共用订单、车辆初态、候选路线和随机种子，使用配对比较。路线的算法候选集仍由传统有向路由器预先生成，实验比较发生在共享候选集的 ETA/延误评估与全局派单，不让 LLM 新造 Link。

核心输出包括逐路段 `travel_time_s`、`signal_wait_s`、`queue_length_veh` 的分解，以及路线 ETA 误差、路线排序 Kendall/NDCG、相对 SUMO 最优候选的 regret、订单服务率与接驾等待。地图上用于交互展示的“8/10 拥堵路段与信号灯近邻配对”只是基于当前 OSM 几何的视觉原型（20 米阈值），不作为正式关系真值；最终必须在 SUMO 网络中验证受控连接。原型播放条的周期、到达率和速度仅供观察机制，不计入实验数据。

### 关键控制

- 固定围栏/缓冲区、OSM 快照、站点 Link 候选、车辆与订单输入、交通需求和信号配置、候选路线集、优化器与词典序目标、最大等待、取消规则和 validator。
- 主比较使用配对种子与成对场景；D2/D3 仅改变地图表达。报告地图/图状态哈希，保证两组读取同一底层数据。
- 记录并冻结 LLM 模型名/版本、推理参数、CLI 版本、输出 token 上限和请求预算。当前阶段不发起模型调用；正式调用预算另行冻结，不自动重试。
- 记录路线估算成本和 SUMO 实际仿真结果为不同字段；优化器时间、模型延迟和模型 token 消耗分开统计。

## 7. 评价指标

**路线与地图读取：**精确/模糊端点分层的 Link 候选召回与精度、候选集规模和匹配置信度；路线有向连续率、单行/转向限制违反率、候选路线合法率、交通状态字段识别准确率、ETA MAE/MAPE、路线排序 NDCG 或 Kendall 相关、相对 SUMO 最优候选的成本 regret、信号等待和拥堵延误的分解误差。

**派单结果：**订单服务率、未分配/超时/取消率、平均与 P95 接驾等待、总接驾时间、载客行驶时间、空驶距离、估算能耗、车辆利用率和订单积压。报告每项指标的分子/分母和场景分层。

**计算成本：**优化器求解时间与 gap/timeout、Agent 评估时间、LLM 调用量/输入输出 token、单轮端到端时延、非法输出和重规划次数。Token 估价与账户实扣区分；失败或未执行调用不得记作零成本。

**地图可读性主证据：**D2 与 D3 的配对差异，包括成本估计误差、路线排序质量、合法候选判断和最终派单结果。D3 超过 D1 不能单独证明地图表达有效，因为方法角色也发生了变化；D5 仅提供有限候选集合下的仿真成本参照。

## 8. 统计、报告与失败处理

使用相同订单、车辆、交通及候选路线种子的配对比较；先报告每个种子，再报告均值/中位数、标准差和配对 95% bootstrap 置信区间。正式任务数在模型结果产生前冻结；因超时、格式错误、非法路线、不可达而失败的任务保留在分母中，并按原因分类。预检、接口 smoke、正式多种子实验分别汇报，不将不同阶段结果合并。

真实地理道路来自 OSM；热度和 OD 来自历史出租车轨迹代理；在线车辆状态、网约车请求到达和交通动态来自实验生成或 SUMO 仿真。论文结论限于冻结的地图版本和仿真设定，不外推到真实平台运营。

## 11. 验收阶段

1. 下载 UCI 原始文件并核对压缩完整性、记录哈希；保存明确的作者、数据集页、DOI 和许可。
2. 完成端点热度与 Porto 候选区预检，冻结围栏规则；下载并核验 OSM 快照、道路通行方向和转向限制。
3. 建立热点到 Link 的候选映射，验证围栏缓冲区连通性、OD 可达率与候选路径覆盖率。
4. 运行小规模 SUMO 预检，核对车辆插入率、信号状态、路段和路线时间输出；确认无死锁，并检查场景级交通负载。
5. 冻结候选生成、Agent 表示、模型输出 schema、优化目标、验证器、输入哈希、种子、正式样本数和请求预算。
6. 先运行不调用模型的传统路线/派单基线；正式 LLM 比较仅在单独预算门禁通过后执行。
7. 完成多种子结果、失败案例、数据来源与许可审计后，再形成论文结论。

当前没有实验结果。本设计不预先声称数据已完成构建、路线成本已测得、SUMO 信号已校准、模型已调用或派单方法已产生性能提升。
